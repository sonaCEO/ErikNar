# API: памятка для фронтенда

Актуальный интерактивный контракт всегда доступен в `/docs`, JSON-схема — в
`/openapi.json`. Все маршруты начинаются с `/api/v1`.

## Каталог

- `GET /catalog/products` — список опубликованных товаров.
- `GET /catalog/products/{slug}` — карточка с вариантами, цветами, размерами и фото.

`variant.id` — главное значение для выбора комплектации. Его нужно хранить после
выбора размера, цвета и управления. Цена приходит в `price_minor`: `1260000` — это
12 600 ₽. Фронт не рассчитывает цену сам.

Для галереи используйте `variant.media`, сортировка уже задана полем `sort_order`.
Изображение с `is_primary=true` считается основным.

## Заявка

`POST /leads` принимает:

```json
{
  "variant_id": "UUID выбранного варианта",
  "customer_name": "Анна",
  "phone": "+7 999 000-00-00",
  "comment": "Позвонить после 18:00"
}
```

Для каждого нажатия кнопки фронт один раз создаёт UUID и передаёт его в
заголовке `Idempotency-Key`. При сетевом повторе нужно отправить тот же UUID и то
же тело. Новое нажатие после успешного ответа должно получить новый UUID.

Успешный ответ:

```json
{
  "public_id": "10000000-0000-4000-8000-000000000001",
  "number": 7,
  "status": "new"
}
```

`public_id` остаётся техническим идентификатором для API. `number` — короткий
неизменяемый номер заявки, который показывается клиенту и сотрудницам как `№0007`.

## Ошибки

Все ошибки API имеют один формат:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Некорректные данные запроса",
    "details": {}
  }
}
```

В логике интерфейса лучше опираться на `error.code`, а `message` показывать
пользователю.

## Авторизация админки

`POST /auth/login` возвращает `access_token`. В защищённых запросах он передаётся как
`Authorization: Bearer <token>`. После `401` нужно вернуть сотрудника на экран входа; после
`403` — показать, что действие недоступно для текущей роли.

Административные `PATCH`-запросы передают `expected_updated_at` из последнего ответа. Если
кто-то уже изменил запись, API вернёт `409 concurrent_update`; фронт должен заново загрузить
данные и попросить повторить изменение.

### Фотографии в админке

`POST /admin/catalog/products/{product_id}/media` принимает `multipart/form-data`:

- `file` — JPEG, PNG или WebP размером до 10 МБ;
- `alt_text` — описание изображения;
- `sort_order` — порядок в галерее;
- `is_primary` — главное фото;
- `variant_id` и `body_color_id` — необязательная привязка к комплектации или цвету.

Список: `GET /admin/catalog/products/{product_id}/media`. Метаданные меняются через
`PATCH /admin/catalog/media/{media_id}`, изображение удаляется через
`DELETE /admin/catalog/media/{media_id}`. Для изменения также нужен `expected_updated_at`.

## Заявки в админке

Сотрудницы и администратор работают с заявками через:

- `GET /admin/leads?page=1&page_size=20` — список;
- `GET /admin/leads/{lead_id}` — карточка вместе с историей действий;
- `POST /admin/leads/{lead_id}/claim` — взять свободную заявку в работу;
- `PATCH /admin/leads/{lead_id}/status` — завершить или отклонить заявку;
- `PATCH /admin/leads/{lead_id}/assignee` — назначить сотрудницу, только для администратора.

Список фильтруется параметрами `status`, `assigned_to_user_id` и `unassigned=true`.
Статусы в JSON: `new`, `in_progress`, `completed`, `cancelled`. В интерфейсе
`cancelled` показываем как «Отклонена».

Изменение статуса и ответственной сотрудницы требует `expected_updated_at` из последней
загруженной карточки. Ответ `409 concurrent_update` означает, что заявку уже изменили в
другой вкладке или через Telegram; нужно обновить карточку перед повторным действием.

Поле `snapshot` содержит название модели, размер, цвет, управление и цену на момент подачи
заявки. Для старых заявок эти данные нельзя пересчитывать по текущему каталогу.
Все ответы административного API по заявкам также содержат поля `public_id` и `number`.
